# ميزانية التشغيل المجاني

> القيم قد تتغير من المزود. نعتمد في التصميم حدًا محافظًا قدره **2 OCPU و12 GB RAM** لـ Oracle A1 Always Free، ولا نرفع حدود الخدمات حتى لو ظهر للحساب رصيد مجاني أعلى.

## Oracle Cloud Always Free — الأساس

الاختيار الأساسي هو `VM.Standard.A1.Flex` في المنطقة الرئيسية للحساب. التصميم لا يفترض GPU ولا يحتاج API ذكاء مدفوع؛ إذا تغيرت حدود Oracle مستقبلًا تبقى نفس البنية قابلة للتشغيل على أي VM ARM/Linux مشابه.

## حدود الذاكرة المقصودة

هذه حدود قصوى للحاويات وليست استهلاكًا دائمًا:

- نظام التشغيل + Docker + cache: نحو 1–2 GB
- PostgreSQL: استخدام شخصي صغير، ويُترك له cache النظام بدل حجز حاوية كبيرة
- SearXNG: **768 MB**
- FastAPI: **512 MB**
- Vision / SmolVLM-256M: **1.2 GB**
- Query Planner / Qwen2.5-0.5B Q4: **1.1 GB**
- Research Worker + FFmpeg/OCR/Whisper: **3 GB**
- WireGuard: **256 MB** عند تشغيل VPN
- Tinyproxy: **64 MB** عند تشغيل VPN

بهذا يبقى هامش للنظام وPostgreSQL والـfilesystem cache ضمن 12 GB. المهمة الثقيلة الوحيدة تنفذ في الوقت نفسه، لذلك لا نحمل عدة نسخ من FFmpeg/Whisper/Vision بالتوازي.

## لماذا نموذجان صغيران؟

- **Vision** يفهم الصورة/لقطات الفيديو ويعطي وصفًا بصريًا موجّهًا للبحث.
- **Planner** لا يجيب عن السؤال؛ وظيفته فقط تحويل الأدلة إلى عدد قليل من استعلامات متعددة اللغات.
- ناتج تحليل الوسائط وناتج الـPlanner يُحفظان في cache أثناء الحاجة، لذلك لا يعاد تشغيل النموذج في كل جولة بحث.

## التخزين

النسخة الأساسية تستخدم Oracle Block Volume فقط، بدون Object Storage إضافي في المسار الأساسي.

- الحد البرمجي الافتراضي لمساحة الرفع المؤقت لكل حساب: **20 GB**.
- الصورة/الفيديو الأصلي يبقى فقط أثناء المهمة التي تحتاجه.
- عند `completed` أو `partial` أو `failed` يحذف الملف الأصلي مباشرة ويصفّر مساره في قاعدة البيانات.
- `stopped` و`needs_context` يحتفظان بالمرفق مؤقتًا حتى يمكن استئناف المهمة أو إضافة معلومة.
- الرفع غير المرتبط بمهمة تنظفه الصيانة بعد TTL كشبكة أمان.
- `/data/tmp` مخصص للملفات المشتقة المؤقتة ويحذف محتواه بعد انتهاء المعالجة.
- Cache التحليل صغير مقارنة بالفيديو الأصلي، ويمنع إعادة استهلاك CPU أثناء المهمة.
- Cache تحليل الوسائط يحمل رقم إصدار؛ إذا تغيرت خوارزمية التحليل يعاد بناء التحليل مرة واحدة ثم يعود لاستخدام cache.
- الأرشيف المحلي على Android/Windows منفصل عن السحابة؛ إذا كان المرفق قد حذف عند النهاية يمكن حفظ النتائج والمصادر فقط.

بهذا تقل مساحة التخزين المطلوبة على السيرفر بدل الاحتفاظ بمقاطع وصور قديمة بلا حاجة.

## VPN

WireGuard وTinyproxy لا يعملان إلا عند تشغيل `docker-compose.vpn.yml`. المسار الافتراضي بدون VPN لا يستهلك ذاكرتهما.

في وضع `auto`:

1. صفحات الويب العامة تُجرب مباشرة أولًا.
2. عند خطأ اتصال/مهلة أو HTTP 451 يمكن إعادة المحاولة عبر مخرج WireGuard.
3. لا يتم تدوير IP بسبب 403/429 أو CAPTCHA.
4. عند تشغيل VPN overlay، يخرج SearXNG نفسه عبر WireGuard أيضًا حتى تشمل التغطية مرحلة اكتشاف النتائج.
5. يمكن إضافة مخارج Proxy مسماة؛ sticky routing يبقي النطاق على نفس المسار ما لم يحدث فشل شبكة مشروع.

## قواعد تمنع استنزاف المجاني

1. حد الطابور **5 مهام** لكل حساب، لكن **مهمة واحدة فقط تعمل فعليًا لكل حساب**.
2. كل جولة تتحقق من عدد محدود من الصفحات ثم تدخل backoff إذا لم تكتمل.
3. 48 جولة بــbackoff متدرج حتى 90 دقيقة تعطي قرابة يومين من الزمن الجداري بدون تشغيل CPU بشكل مستمر.
4. أقصى المرشحين مضبوط برمجيًا بدل crawling غير محدود.
5. HTTP أولًا، ولا يوجد متصفح كامل في المسار الافتراضي.
6. الفيديو لا يحلل frame-by-frame؛ يبدأ بلقطات تغيّر المشهد ويستخدم توزيعًا زمنيًا فقط إذا كانت المشاهد المميزة غير كافية.
7. اللقطات شبه المكررة تُزال بـpHash قبل OCR/Vision لتقليل CPU.
8. Vision يطبق على عدد أقل من اللقطات (`VISION_MAX_FRAMES=4`) لتقليل CPU.
9. Whisper يحلل حدًا زمنيًا مضبوطًا بدل فيديو مفتوح النهاية.
10. بحث الوسائط يحجز جزءًا من نفس ميزانية المرشحين لنتائج الصور؛ لا يضاعف العدد الكلي لمجرد أن البحث بصري.
11. صورة نتيجة الويب تُقرأ بحد أقصى **6 MB** وتُقارن بعدة بصمات، فلا نحمّل ملفات صور ضخمة في الذاكرة.
12. روابط النتائج تنظف من معاملات tracking الشائعة حتى لا نفحص نفس الصفحة عدة مرات.
13. لا يوجد API ذكاء مدفوع في المسار الأساسي.
14. لا يوجد Redis أو Elasticsearch.
15. الحد الافتراضي للنتيجة 10 عناصر.

## النتيجة العملية

هذه البنية للاستخدام الشخصي/عدد أجهزة محدود، وليست خدمة عامة لآلاف المستخدمين. التصميم يستهلك وقتًا أطول عند الحاجة بدل دفع تكلفة GPU: مهمة واحدة نشطة، نماذج محلية صغيرة، cache واسع، وبحث على جولات.
