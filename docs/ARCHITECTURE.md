# معمارية البحث العميق

## المسار

```text
Android / Windows (Flutter)
        |
        v
    FastAPI
        |
        +---- PostgreSQL (الحسابات/المهام/النتائج + Queue)
        |
        +---- /data/uploads (رفع مؤقت للصور/الفيديو)
        +---- /data/tmp     (تحليل مشتق مؤقت فقط)
        |
        v
 Research Worker
        |
        +---- SearXNG
        +---- HTTP fetch + Trafilatura
        +---- FFmpeg / OCR / Whisper / Vision عند الوسائط
        |
        v
 WireGuard / Egress على نفس السيرفر
        |
        v
      Internet
```

## سياسة الوسائط

1. الصورة أو الفيديو يرفع إلى مساحة الحساب المؤقتة في `/data/uploads` ويرتبط بالمهمة فقط أثناء الحاجة إليه.
2. يبقى المرفق متاحًا خلال البحث، وكذلك عند `stopped` أو `needs_context` حتى يمكن استئناف المهمة أو إضافة معلومة.
3. عند `completed` أو `partial` أو `failed` يحذف Worker الملف الأصلي مباشرة ويصفّر `input_url` في PostgreSQL.
4. الملفات المشتقة مثل keyframes والصوت المؤقت وملفات Vision تستخدم `/data/tmp` فقط وتحذف بعد انتهاء المعالجة.
5. endpoint المرفق محمي بنفس Device Token ولا يسمح لجهاز من حساب مختلف بتنزيل الملف.
6. عند أرشفة مهمة على جهاز بينما المرفق ما زال موجودًا يمكن تنزيل نسخة محلية قبل إلغاء المهمة. إذا كان البحث قد انتهى وحُذف الأصل، يحفظ الأرشيف النتائج والمصادر فقط.
7. الأرشيف المحلي غير متزامن: Android وWindows لكل منهما مجلد أرشيف مستقل.
8. إلغاء المهمة أو حذفها يحذف أي مرفق مؤقت متبقٍ فورًا.
9. الرفع الذي لم يرتبط بمهمة تنظفه الصيانة بعد TTL كشبكة أمان للحوادث/الانقطاع.

## الطابور

كل حساب يملك حتى 5 مهام غير منتهية. Worker ينفذ مهمة ثقيلة واحدة في الوقت نفسه ويمنع مهمة متوقفة أو في backoff من تجميد حساب آخر. داخل الحساب يحافظ على FIFO.

البحث الطويل يعمل على 48 جولة مع backoff متدرج يصل إلى 90 دقيقة؛ مجموع الانتظار يقارب 48 ساعة مع وقت المعالجة الفعلي، لذلك يمكن أن يستمر البحث قرابة يومين بدون تشغيل CPU باستمرار.

## استمرار البحث

- المهمة النصية المكتملة/الجزئية يمكن إعادتها للطابور لاحقًا لأنها لا تحتاج ملفًا أصليًا.
- مهمة الصورة/الفيديو لا يمكن إعادة تشغيلها بعد حذف المرفق النهائي؛ يلزم رفع الصورة/الفيديو من جديد. هذا مقصود حتى لا نخزن وسائط المستخدم بعد انتهاء البحث.
- إذا كانت المهمة `stopped` أو `needs_context` وما زال المرفق المؤقت موجودًا، يمكن استئنافها أو إضافة معلومة لنفس المهمة.

## لماذا PostgreSQL Queue؟

لتوفير خدمة وذاكرة إضافية. الأقفال والمعاملات في PostgreSQL تمنع تجاوز سعة الطابور وتضمن أن Worker واحد فقط يطالب بالمهمة التالية. للاستخدام الشخصي لا نحتاج Redis في البداية.

## VPN

الـVPN داخل السيرفر وليس الجهاز. WireGuard يطبق على مستوى Linux أو Network Namespace. التطبيق لا يحصل على مفاتيح VPN. `EGRESS_PROXY_URL` مخصص لوضع متقدم يكون فيه VPN في namespace/gateway منفصل ويصل إليه الـWorker عبر proxy.

## Android + Windows

نفس Flutter client ونفس الحساب السحابي للمهمات والطابور والنتائج. ربط الأجهزة يتم برمز مؤقت. المرفقات الأصلية ليست أرشيفًا سحابيًا دائمًا، والأرشيف المحلي وحده لا يدخل في المزامنة.
