# البحث العميق — HAI_SERCH

تطبيق بحث طويل المدى يعمل من السحابة ويزامن نفس المهام والنتائج بين Android وWindows.

## الهدف

- إدخال نص، صورة، أو فيديو.
- استمرار البحث حتى بعد إغلاق الأجهزة.
- تحليل بصري فعلي للصورة ولقطات الفيديو، وليس OCR فقط.
- جمع نتائج موثقة وترتيبها حسب المطابقة النصية والبصرية.
- مزامنة الطابور والمهمات السابقة والنتائج بين Android وWindows.
- VPN / Egress داخل السيرفر فقط.
- تشغيل شخصي بتكلفة أساسية 0 قدر الإمكان.

## كيف يتم تحليل الصورة والفيديو؟

### الصورة

```text
الصورة
 -> Vision محلي
 -> OCR متعدد اللغات
 -> بصمات بصرية pHash + قصّات مركزية
 -> Query Planner متعدد اللغات
 -> SearXNG (بحث ويب + صور)
 -> مقارنة صور النتائج بالبصمة
 -> فحص صفحات المصادر
 -> ترتيب النتائج
```

### الفيديو

```text
الفيديو
 -> FFmpeg: لقطات موزعة على كامل المدة
 -> Vision لعدد محدود من اللقطات
 -> OCR متعدد اللغات
 -> Whisper.cpp للحوار/الصوت
 -> بصمات بصرية لعدة لقطات
 -> Query Planner متعدد اللغات
 -> بحث ويب + صور
 -> تحقق وترتيب
```

تحليل الوسائط والتخطيط يُحفظان في cache ولا يعاد تشغيل النماذج في كل جولة.

## دورة حياة الصورة والفيديو

1. يرفع المرفق إلى السحابة ويرتبط بالمهمة.
2. يظل موجودًا طوال البحث، حتى لو استمر ساعات أو أيام.
3. عند اكتمال البحث تبقى المهمة والمرفق والنتائج في **المهمات السابقة** السحابية، ويمكن فتحها من Android أو Windows المرتبطين بنفس الحساب.
4. يمكن اختيار **استمرار البحث** لنفس المهمة مع نفس المرفق والنتائج السابقة، ويبدأ من مرحلة بحث أعمق بدل إعادة الجولة الأولى.
5. عند اختيار **أرشفة** من جهاز معين، ينزل التطبيق نسخة كاملة إلى تخزين ذلك الجهاز: المرفق + النتائج + المصادر. أرشيف Android مستقل عن أرشيف Windows ولا تتم مزامنته.
6. حذف عنصر من شاشة الأرشيف يحذف النسخة المحلية لذلك العنصر فقط بعد تأكيد المستخدم، ولا يحذف المهمة السحابية.
7. المرفق السحابي يحذف عند إلغاء المهمة أو حذف المهمة السحابية نهائيًا أو اختيار حذف المرفق السحابي صراحةً.
8. إطارات الفيديو وملفات العمل المؤقتة تحذف بعد انتهاء الحاجة إليها.

## الطابور

- حد أقصى 5 مهام غير منتهية لكل حساب.
- مهمة واحدة فقط تعمل في الوقت نفسه.
- بقية المهام تنتظر بنظام FIFO وتبدأ تلقائيًا بعد انتهاء السابقة.
- إيقاف المهمة الأولى مؤقتًا يبقي ما خلفها في الانتظار حتى تستأنفها أو تلغيها.

## البنية المختارة

- **Client:** Flutter (Android + Windows من قاعدة كود واحدة)
- **API:** FastAPI / Python
- **Database + queue:** PostgreSQL فقط، بدون Redis
- **Search:** SearXNG + HTTP crawler خفيف
- **Vision:** SmolVLM-256M محلي عبر llama.cpp
- **Planner:** Qwen2.5-0.5B Q4 محلي عبر llama.cpp
- **Media:** FFmpeg + Tesseract OCR + Whisper.cpp + ImageHash
- **Server:** Oracle Cloud Always Free Ampere A1
- **VPN:** WireGuard + Tinyproxy داخل السيرفر
- **Updates:** GitHub Releases

## VPN

التشغيل العادي يعمل مباشرة. عند إضافة WireGuard client config وتشغيل `docker-compose.vpn.yml`:

- يخرج SearXNG عبر الـVPN.
- يمكن للـWorker التحويل بين direct وVPN للصفحات العامة.
- لا يوجد تدوير IP عشوائي.
- 403/429/CAPTCHA لا تسبب تبديلًا تلقائيًا للمسار.
- مفاتيح WireGuard مستثناة من Git ولا ترفع إلى GitHub.

راجع `docs/VPN.md` للتشغيل.

## فلسفة استهلاك المجاني

1. لا يتم تحليل الفيديو frame-by-frame؛ تؤخذ لقطات موزعة فقط.
2. Vision يطبق على عدد محدود من اللقطات.
3. Query Planner ينتج عددًا محدودًا من الاستعلامات ويستخدم cache.
4. نتائج البحث وتحليل الوسائط لها cache لمنع إعادة العمل.
5. المهام تستخدم PostgreSQL queue بدل Redis.
6. ملفات العمل المؤقتة فقط تنظف آليًا؛ مرفقات المهمات السابقة لا تحذف زمنيًا.
7. لا يوجد API ذكاء مدفوع ضمن المسار الأساسي.
8. لكل مهمة ميزانية موارد مع بحث على جولات وbackoff بدل إبقاء CPU مشغولًا بلا فائدة.

راجع `docs/ARCHITECTURE.md` و `docs/FREE_TIER_BUDGET.md` للتفاصيل.
